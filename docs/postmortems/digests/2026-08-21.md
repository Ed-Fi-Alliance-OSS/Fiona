## Steering-file edit proposed

**One edit: add "Validate test intent" to the Standard path in
`.github/copilot-instructions.md`.**

**Evidence:** Correctness-class review comments in 3 of 9 human PRs (PR-72,
PR-78, PR-86) indicate that behavioral mismatches between test intent and
implementation are reaching review rather than being caught earlier.
This is a repo-convention observation, not an agent-performance claim (agent
cohort is empty). The "Validate test intent" step already exists in the
detailed `coding-agent.agent.md` playbook (Standard path, step 2); adding it
to the always-on `copilot-instructions.md` baseline closes the gap and mirrors
the rule consistently. Per the "Mirror edits across duplicated rules" policy,
no change to `coding-agent.agent.md` is needed — it already carries the step.

The edit inserts a new numbered step between "Plan first" and "Scope-drift
check" in the Standard path section.

**Cumulative note:** The identical edit was proposed by the prior synthesis run
(`copilot/postmortem-synthesis-2026-08-17`) on the same batch of records. This
run re-proposes it because the prior PR was not merged before this synthesis
cycle ran. If the prior PR is merged, this PR should be closed.

## Ticket-description quality observations (prose)

These are observations about tickets in the human cohort, offered as process
suggestions. They are not written to Jira.

**PR-62 / AI-133+AI-134 — keyword routing and help discovery:** Spanning two
Jira keys in a single PR (14 files, 708 additions, 8 review cycles) suggests
the two concerns should be independently ticketed. Future tickets in this area
would benefit from explicit acceptance criteria per command keyword — what
exact response each command returns, and how unknown commands are handled —
so that the implementer can write narrowly targeted tests before coding.

**PR-63 / AI-122 — human escalation:** Forty-three commits and 15
fix+feature follow-up commits suggest scope expanded after work began. Future
escalation tickets would benefit from separating the Slack UX interaction
pattern from the routing and handler plumbing so each can be reviewed and
merged independently.

**PR-74 / AI-175 — longitudinal usage trends:** The largest PR (5 501
additions, 40 files, 56 commits). Longitudinal analytics naturally decomposes
into: data-layer query, formatter/presenter, Slack delivery, and test
coverage. Future tickets at this scale should name those slices explicitly so
the reviewer can focus on one area at a time.

**PR-86 / AI-188 — post-mortem improvement loop:** 6 306 additions across 19
files with a rework-class review comment. The ticket presumably described the
overall loop architecture. Adding acceptance criteria that enumerate the
specific files, workflows, and behaviors the implementation must produce would
let reviewers verify completeness against a checklist.

## Ticket-description suggestions (prose)

These are observations for future ticket authors, not written back to Jira.

**Schema completeness for the capture script (AI-188 follow-up or new ticket):**
The post-mortem improvement loop depends on the `authorKind` field to
distinguish coding-agent work from human work. Ten of the thirteen records in
this batch pre-date the field (schema v1). A back-fill pass — or a migration
that stamps `authorKind: human` on all existing v1 records — would allow future
synthesis runs to correctly compute the agent cohort even for the historical
archive. A ticket for this work should specify: (a) the exact field and allowed
values (`agent`, `human`, `dependabot`, `other-bot`); (b) whether back-fill
should be done in-place or by re-running the capture script; and (c) the
acceptance criterion (every file in `processed/` has a top-level `authorKind`).

**Coding-agent piloting (new ticket):** The Fiona repo has invested in
coding-agent steering infrastructure (PR-85, PR-92) but has not yet produced
any `authorKind: agent` records. A ticket to run the first end-to-end
coding-agent task — capturing its output as a `PR-*.json` record — would
validate the pipeline and give the post-mortem loop its first real evidence
batch.

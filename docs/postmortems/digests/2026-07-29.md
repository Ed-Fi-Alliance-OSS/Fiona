## Themes (with cited evidence)

1. **Clean quality baseline for the coding agent (7 of 7).** Zero
   rework-after-review, zero CI failures, zero correctness comments, no
   undeclared dependencies, tests present wherever source changed. The two
   copilot-bot-authored PRs (PR-82 large feature with tests; PR-90 a scoped
   Azure SAS bug fix) both merged clean. The existing steering (fail-first TDD,
   green-before-PR, license headers, right-sizing, scope-drift, Jira source of
   truth) is already reflected in the observed behavior. Nothing in the data
   argues for changing it.

2. **Bootstrapping-sequencing miss on AI-184 (2 of 7, non-generalizing).**
   PR-89 and PR-92 review threads paraphrase to: a prior PR documented the
   coding agent but did not register the selectable `.agent.md`, so PR-89/PR-92
   had to complete the "actually make it selectable" step; and there is
   unverified behavior around how the "notify the requester on an incomplete
   ticket" path manifests when triggered from Jira (may need a fork/second repo
   to exercise). Both are about *building the agent itself* and about
   *provisioning/integration owned by the Technology team* — not about how the
   agent executes an assigned ticket. Treated as a one-time bootstrapping event
   (n effectively 1 initiative), not a repeatable task-execution pattern, so it
   does not justify a steering edit.

3. **Ticket quality varied and it showed (qualitative).** AI-191 (PR-90) was an
   exemplary bug ticket — exact error output, reproduction steps, environment,
   and even a viable workaround — and produced a clean, tightly-scoped fix.
   AI-184 (PR-85 → PR-89 → PR-92) carried more abstract acceptance criteria
   ("create a baseline harness", "optimize it to perform TDD", "minimize HITL
   cycles"), which correlates with the multi-PR iteration to converge on a
   shippable shape. See ticket-description suggestions below.

## Ticket-description suggestions (prose, not written back to Jira)

- **Give feature tickets a concrete definition of done.** AI-184's criteria
  were outcome-abstract; a checklist of observable end states (e.g. "a
  selectable `.agent.md` exists AND `copilot-instructions.md` references it AND
  the incomplete-ticket path has been exercised once") would likely have
  collapsed the PR-85 → PR-89 → PR-92 sequence and avoided the
  documented-before-registered miss.
- **Keep writing bug tickets like AI-191.** Exact error text, reproduction
  steps, environment, and a candidate workaround are what let PR-90 land as a
  clean, single-purpose fix. This is the pattern to standardize for bug intake.
- These are suggestions for humans authoring tickets; nothing was written to
  Jira (read-only access only).
